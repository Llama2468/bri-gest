1. Executive summary

Endocrine Bri-gest is a browser-based, zero-cost, weekly literature digest for clinicians undertaking or maintaining competency in endocrinology and diabetes. It addresses a specific practical problem: the endocrine literature is large, rapidly evolving, and distributed across dozens of journals and subspecialties, and no free tool provides structured, CPD-aligned, weekly surveillance of it at the domain and subdomain level.

The application runs as a single HTML file opened directly in a browser. It queries PubMed's open-access E-utilities API in real time, returning verbatim abstracts from indexed articles. There is no server infrastructure, no subscription, no AI-generated content, and no hallucination risk. Search strategies are derived from published guideline search methodologies, and every article links directly to its PubMed record and, where available, the journal full text via DOI.

Key design principle: this tool is a literature surveillance aid, not a clinical decision support system. All content is sourced verbatim from PubMed. No AI summarisation or interpretation is applied at any point. The clinician reads primary abstracts and makes their own judgement about relevance and quality.

Lay-level description

Think of Endocrine Bri-gest as a structured, personalised journal table of contents that arrives whenever you open it, organised by the topics that matter to your practice. Instead of manually searching PubMed or relying on journal alerts across a dozen sources, it pulls together the most recent literature across ten RACP-aligned clinical domains — from Diabetes and Thyroid to Neuroendocrine Tumours and Endocrine Oncology — and presents it in a clean, readable interface. Each article shows the journal name, study-type badge, impact factor, and publication date at a glance. Clicking an article reveals the full abstract. Articles can be saved for later or marked as read. Filters narrow to specific study types or high-impact journals. The whole thing opens like a document; there is no login, no app store, and no ongoing cost.

Technical-level description

Endocrine Bri-gest is a self-contained HTML5 single-page application. The data layer is entirely client-side: the application constructs PubMed Entrez E-utilities queries (esearch + efetch, both CORS-permissive) from pre-defined, RACP-curriculum-aligned MeSH and tiab search strategies, fetches XML responses, parses them via the browser's native DOMParser, and renders the result. State (bookmarks, read status, theme preference, text-size step, subdomain selection) persists in localStorage where available. A six-hour in-memory cache prevents redundant fetches within a session. There is no build step and no dependency on npm or any framework at runtime.

2. Clinical purpose & rationale

The problem

Endocrinology and diabetes is a broad specialty with high-velocity literature across multiple subspecialties. A Fellow or Consultant maintaining RACP Advanced Training competency must monitor developments in at least ten distinct clinical domains simultaneously. The practical barriers:

  • Journal alert proliferation — emails from a dozen journals create inbox noise without clinical structure.
  • Domain fragmentation — a study on SGLT2 inhibitors, a case series on ICI-induced hypophysitis, and a trial of romosozumab all require different alert strategies.
  • Study-type signal/noise — PubMed returns case reports, letters, and editorials alongside high-impact trials without automatic prioritisation.
  • Time constraint — the practical window for literature review in a busy clinical week is short; tools must be fast and friction-free.

The solution

Endocrine Bri-gest is structured around RACP curriculum domains rather than journals, with pre-built search queries derived from published guideline search strategies. Study-type filters allow rapid signal prioritisation. The impact-factor display and filter allow quality stratification without requiring the user to know journal rankings. The workflow requires opening one file and clicking a tab.

CPD relevance: RACP Maintenance of Professional Standards (MOPS) requires documented engagement with the medical literature as part of continuing professional development. The saved-article and read-tracking features provide a record of literature reviewed that can support CPD documentation.

4. Application architecture

Design philosophy

Three constraints shape every technical decision:

  • Zero infrastructure — no server, no database, no authentication service, no build pipeline. The file must be openable by any clinician on any computer with a browser.
  • Zero hallucination — all article content is verbatim from PubMed. No AI summarisation, paraphrasing, or interpretation at any stage. Non-negotiable for a CPD tool.
  • Zero cost at scale — NCBI E-utilities is a free public API with permissive CORS headers.

File structure

The application is a single HTML file. There are no runtime dependencies beyond the PubMed E-utilities API and two self-hosted webfont families (Newsreader, IBM Plex Mono — served from /fonts/, not a font CDN).

CSS: embedded in a <style> tag. Two themes (light, dark) implemented via CSS custom properties, shared across the hub, this tool, and General Medicine Bri-gest. Theme switching requires only a data-theme attribute change on <html>. A --tsize multiplier drives a three-step text-size control.

JavaScript: embedded in a <script> tag. No framework, no transpilation, no bundler. Modern syntax throughout — const/let, arrow functions, template literals, async/await — with one deliberate exception: no optional chaining (?.) or nullish coalescing (??) operators anywhere, since both cause a full SyntaxError that silently kills the entire script on iOS Safari below 13.4. This is a narrower, more accurate constraint than "ES5-compatible" — the codebase is modern ES6+ minus those two specific operators.

Data: TOPICS array (10 objects, 53 subdomains total), JOURNAL_GROUPS array, IF_MAP object (500+ entries). All embedded in the script.

5. Feature catalogue

Topic lanes & subdomain pills

One tab per RACP domain, with a vertical divider separating core domains from extended ones. Clicking a tab loads the broad domain query; a row of scrollable pills beneath the topic title selects individual subdomains, each independently cached.

Filters

FilterFunction
Date rangePast 7/14/30 days. reldate parameter. Clears cache on change.
Study typeAll / RCT / Systematic review / Meta-analysis / Guideline / Review. [pt] filter appended to query.
Impact factorAny / ≥5 / ≥10 / ≥20 / ≥40. Post-fetch client-side filter, no re-fetch required.
Journal filterMulti-select from curated journal groups. Activates Journal View. Persisted to localStorage.

Article cards

Each card shows journal name (coloured by domain, theme-aware — each domain accent has a separate light/dark hex tuned for contrast, not one fixed colour reused regardless of theme), IF badge, study-type badge, publication date, and PMID. Correspondence items (Letter, Comment, Editorial, Erratum) are identified from PubMed's PublicationType field — never hand-set or inferred — and de-emphasised.

Saved articles & read tracking

Articles bookmark across sessions via localStorage. Unread counts badge each topic tab. A warning banner displays if storage is unavailable (Private Mode or restricted context).

Search strategy audit panel

Shows every topic lane's shown/total result count, a "Verify on PubMed" link, the raw query string sent to NCBI, and the NCBI query translation.

Themes & text size

Two visual themes (light, dark), shared token-for-token with the hub and General Medicine Bri-gest. A three-step text-size control (Aa button) scales article typography via --tsize. Both persist to localStorage with legacy-value migration for anyone still on the old four-theme system (midnight/clinical/slate/amber → dark/light).

6. Search strategy framework

Each domain has two query tiers: a broad domain-level query (union of all subdomain heads) and individual subdomain queries. Where a published search strategy exists from a major guideline or systematic review, that strategy is adopted as the base and extended with tiab terms for recently coined terminology not yet indexed in MeSH.

MeSH terms anchor the established literature; tiab terms capture new terminology before MeSH indexing occurs — essential for MASLD/MAFLD nomenclature changes, newly approved drugs, and terminology consensus changes (e.g. AVP deficiency replacing "CDI"). See the search strategy reference for the full query text and the Boolean-precedence framework governing how they're constructed.

9. Current status against the previous roadmap

The v5.4 document's roadmap is reconciled here against what has actually shipped, rather than left to silently go stale again:

  • Theme consolidation (one dark, one light) — done, v5.9, though executed as a full palette replacement rather than picking one of the original four.
  • Dark-mode contrast review — done for the specific save/star-button defect found in production (was ~1.2:1 contrast, now 6.18:1). A systematic WCAG AA audit across every element has not been run.
  • Web Share export fallback — done, v5.9. Routes through navigator.share on iOS Safari when file-sharing is supported; unchanged elsewhere.
  • Save files / IndexedDB — not done. Still localStorage-based; IndexedDB remains under consideration with no defined migration plan.
  • Build-time validation — partially done. The preflight-v5.4.py static checker this document previously described (optional-chaining detection, font-CDN detection, etc.) does not exist anywhere in this repository's history — confirmed by search, 2026-07-26. What exists instead is narrower: .github/workflows/syntax-check.yml, a CI gate that runs node --check against each tool's extracted script on every push. It catches JS syntax errors (the class of defect that shipped in v5.8) but not the broader iOS-compatibility pattern class the old checker described. That gap is real and unaddressed.
  • NCBI API key, abstract annotation, custom query lanes, SJR integration, email delivery — not done, not currently planned.
